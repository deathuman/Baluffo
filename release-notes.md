## [0.2.152] - 2026-09-21
### Changed

Across the four real feed rows that waste averaged 48.6% at 675px and **63.4% at 900px**, and because the track count never changed the card was exactly as tall at 900px as at 430px: `.jobs-list` measured 924.19px at 900, 811, 760, 700, 675 and 600px, identical across a 300px range of widths. The tracks are now `repeat(auto-fit, minmax(min(12.75rem, 100%), 1fr))` with a `0.4rem 0.9rem` gap and `.col-title` spanning `1 / -1`, so the four metadata cells pair two per line where the width allows and collapse to one where it does not, with no extra breakpoint: row height drops from 246.25px to **147.38px at 900px** (three columns) and **181.67px at 675px** (two columns, −26%), and waste falls to 10–24%. `.col-title` spans because it holds the freshness dot, the title, the new badge, the lifecycle badge and the sector line, which must stay together on one line. **The floor value is measured, not chosen.** The longest value that cannot wrap is the single-word company `Blackbirdinteractive` (119px intrinsic), and every width from 900px down to 320px was swept at 1px steps to find the smallest floor that never clips it. At `12.5rem` the tracks are 200.55px wide between 761px and 764px, and the label box is still 72px above the 760px breakpoint, leaving the value 117.36px — a **1–2px clip that the current layout does not have**, which would have been a regression introduced by the fix. `12.75rem` (204px) is the smallest floor with zero new clips; it is smaller than the Saved card's `18rem` because the Jobs feed's longest company is 119px against Saved's `Really Long Company Name International B.V.`, and the difference is recorded in the rule's comment. The `min(…, 100%)` cap is load-bearing for the same reason it is in Saved: a bare `minmax(12.75rem, 1fr)` is a hard 204px floor that overflows the 189px content box at 320px. Desktop is untouched — verified at 901, 950, 1024, 1100, 1280, 1440 and 1920px as byte-identical six-column tracks (`436.297px 208.453px 184.219px 118.391px 102.391px 83.1875px` at 1440px, row height 54.63px), and the 900/901px handover was swept at 1px steps across 895–1035px with **zero widths in a broken state**: 900px is the last card, 901px the first table. Six new guard tests in `tests/frontend/unit/jobs-css-guards.test.mjs` cover the pairing, the `min()` cap, the floor value, the title span, the column gap and the desktop guard, and all eleven mutations applied to them were caught by exactly the intended assertion — including one that found the gap assertion missing, which is what pairs the columns visually.

- **The Saved job card now pairs its metadata fields instead of stacking one per line.** Below 901px the row becomes a card, and that card was a single `1fr` column, so each of the six cells owned a full-width line: at 811px every cell measured **648px wide while the values inside them were 27–115px**, spending 322px of height on five short strings and leaving roughly 450px of every line empty — the card was 606px tall for a job that renders in 139px on desktop. The tracks are now `repeat(auto-fit, minmax(min(18rem, 100%), 1fr))`, so short fields pair up two per line where the width allows and collapse to one line where it does not, with no extra breakpoint: measured **532px** at 900px and 811px (was 606px), 596px at 700px, 658px at 600px, and no truncation of the title, company, contract or type anywhere from 900px down to 480px. The `min()` around the floor is load-bearing rather than cosmetic — a bare `minmax(18rem, 1fr)` is a hard 288px floor, and at 360px the row's content box is 252px, so the track overflowed it by 36px and the title's clip box ran 30px underneath the delete button; this was caught only by measuring the rendered page at 360px, where the earlier widths looked clean. Four alignment defects went with it. The cell labels were `flex: 0 0 72px` with mixed `text-align` — three left, three centred — so with glyph widths of 26–61px the labels began at x=101, 106, 123… and every value started at x=191 regardless of its label's width; they are now a fixed `4.6rem` column, left-aligned, which is what actually puts the values on one x. Contract and Type are centred chips on desktop, which on a card left them floating away from their own label, and `.saved-link-actions` is `width: 100%; justify-content: center`, which put "No link" at x=431 in the middle of the card while the other five values started at x=191; both are now left-aligned. The company name is `nowrap` + ellipsis on desktop where its column is fixed, which in a fluid card truncated a real name to `Really Long Co...`; it now wraps, so company truncation is gone at every width and the pre-existing 390px title truncation improved from `+110px` to `+90px`. The delete button no longer floats in the metadata block: it was `position: absolute; top: 50%` on a 322px row, which put it at y=769 — **below the title it deletes and alongside the COMPANY cell** — while reserving a 68px left gutter for the full height of the card; it is now pinned to the title's top-right corner (`left: auto; right: 0.85rem; top: 0.9rem`), which reclaims that gutter. The title reserves `padding-right: 2.6rem` for it, verified at 360px and 320px where the gap between the title's clip edge and the button is `+6px` rather than negative. Separately, `renderMissingInfoChips` no longer repeats what the cells below already say: it emitted "No link" while the LINK cell rendered "No link" and "No contract" while CONTRACT rendered "Unknown", stating the same two facts twice in one card. Desktop is untouched — a computed-style diff against `HEAD` at 1440px, 1280px, 1200px and 901px shows identical tracks (`325.016px 216.016px 139.875px 115.188px 99.1875px 113.141px`), row height `139`, label `content: none`, `titlePadRight 7.04px` and `nowrap`, so every added rule sits inside the mobile block. Ten mutations across `styles/saved.css` and `render-controller.js` were each caught by exactly the intended assertion, including one that exposed a vacuous check: `padding-right: 0` satisfied a bare `padding-right` match while leaving the title free to run under the button, so the assertion now requires a non-zero value.

- **Admin no longer hides its own tables at narrow widths, and the Jobs card layout aligns consistently.** This corrects an earlier claim in this same window: Admin was reported as unaffected by the narrow-width work, but that conclusion came from a page-level overflow metric that reads `-10` on Admin at every width. Admin was in fact the worst case, because its overflow is swallowed by an `overflow: hidden` ancestor (`.jobs-list`) instead of reaching the document, so the metric could not see it. The mechanism is the same specificity tie as the Jobs/Saved defect: `.admin-row-header, .admin-user-row` in `styles/admin.css` is `(0,1,0)` and *ties* the shared stacked-card block in `styles/components.css` at `(0,1,0)`, but `admin.css` loads after `components.css`, so the page sheet won the tie and the mobile block was dead — the header stayed visible *while* the inline `::before` labels were injected, so every field was labelled twice. The eight-column geometry, the `border-top: none` and the `border-radius: 0 0 8px 8px` now live behind `@media (min-width: 901px)`, and the tracks use a `0` floor instead of `minmax(160px,…) minmax(180px,…)`. Measured before, the content clipped and **not reachable by scrolling** (every container is `overflow-x: hidden`): `#admin-users-list` 111px at 1100, 310px at 901, 522px at 717, **849px at 390**; the three source lists up to 526px; `.admin-ops-current-runs` up to 335px. After: **zero clipped containers at every width from 360px to 1440px**, with the source lists reachable by horizontal scroll and their header and body scrolling together (verified: both move exactly 176px at 717px, columns aligned before and after). Two further traps surfaced only under that reachability check. The source tables' fluid tracks carried `minmax(138px, 1fr)`-style floors, so at 901px the seven columns could not shrink to the container and each row clipped its *own* last column against its `overflow: hidden` — the row never overflowed its parent, so the parent never scrolled and the column was unreachable; those floors are now `0`. And `.jobs-table-body` is `overflow-y: auto` for the virtual window, which also makes it a *horizontal* scroll container, so leaving the header and body at container width clipped each row's last column and kept the parent from ever scrolling; both are now sized `max-content` so `.jobs-list` is the single horizontal scroller and the two stay in step. Desktop is unchanged — a 13-property computed-style diff against `HEAD` at 1440px, including every source column's exact left offset and width, the user-row tracks, and document height `4995`, is identical. Two Admin-specific constraints shaped the fix: all 105 `.admin-source-row` elements also carry `.admin-user-row`, so the shared card block matches them and they must be explicitly restored to table treatment (their cells have no `data-label`, so an injected `::before` would render as a blank 100px label); and `display: grid` lives only in the desktop rule, so guarding it alone silently collapsed the rows to `display: block` and clipped them vertically by 99px until it was kept unguarded. Separately, on the Jobs page the stacked card had mixed alignment — title/company/location left-aligned but contract/type centred — because unguarded `.jobs-page .col-contract` / `.col-type` / `.col-save` `(0,2,0)` rules beat the shared `flex-start` `(0,1,0)`; the save row was also clustering its label and button mid-card instead of the label-left / control-right rhythm every other row follows. Those rules, plus the `white-space: nowrap` on `.job-title-compact` / `.job-company-compact` that defeated the shared block's intended wrapping, now live behind the same `@media (min-width: 901px)` guard. A long title that was previously ellipsized to one line (`1144px` of text in a `586px` box) now wraps to two lines with nothing hidden. Two new guard tests fail if any of these rules returns outside its width guard; both were mutation-verified to be non-vacuous (11 separate mutations, each caught by exactly the expected assertion). A follow-up pass then corrected two things this bullet got wrong and closed the defects it had left open. **The source tables' tracks had to stop being fluid.** The header and the rows are two *separate* grid containers (`.jobs-table-header` and `.jobs-table-body`), so every track that resolves against its own content desynchronises them as soon as the table scrolls: `max-content` sizes the header's `Name` to its 35px label while the row sizes the same column to its 228px value, and `fr` resolves against the header's width rather than the body's. The earlier `minmax(0, 1fr)` pair looked harmless because both containers happened to be the same width, which is exactly why the desync only appeared once the body became `max-content`. The seven columns are now container-independent fixed tracks (`52px 23rem 96px 17rem 84px 68px 16rem`), sized from the measured per-column content maxima across all 103 rows of the three lists (Name 362px, Studio 265px, Approval 250px) so nothing truncates; measured header/row cell offset is ≤1px before and after a 200px scroll, at every width from 390px to 1440px. **The comment claiming these cells "carry no inline labels" was factually wrong** — all seven carry `data-label` (`Select, Name, Adapter, Studio, Status, Jobs, Approval`) — so the `content: none` suppression is now justified by the duplicate-label reason that is actually true, and the header's own visibility rule was widened to cover `.admin-row-header` too, because `components.css` hides *both* classes in its `(max-width: 900px)` block and this file's base `display: grid` no longer reaches that band now that the geometry is guarded. Two further defects were found and fixed in the same pass. The Admin user table starved rather than overflowed: at 905px its Name and User ID cells measured 10px and 11px, wrapping one character per line into a 155px row, which neither an overflow metric nor a clipping check can see because the text fits its own box — it is simply unreadable. It now borrows the stacked-card treatment for `@media (min-width: 901px) and (max-width: 1100px)` only, returning to the eight-column table at 1150px where the tracks are readable again. And the Operations History table was clipping its last column *unreachably* from ~1000px down to 521px (measured 80px at 1000px, 175px at 905px, 252px at 810px, 462px at 600px) because the rows inherit `overflow: hidden` from `.admin-source-row` while their track floors exceeded the container: the row never overflowed its own parent, so no ancestor scroller had anything to scroll. Its tracks are now fixed and its wrapper is the horizontal scroller, with the `max-content` sizing guarded to `@media (min-width: 521px)` because the five fluid columns in the `520px` block already fit and `max-content` there measured 1382px of row inside a 354px wrapper. The stale claim in the `.admin-ops-current-runs` comment — that an `overflow-x: auto` on that wrapper had solved the clipping — was wrong and is gone.

- **The Jobs and Saved tables no longer overflow the page at narrow widths.** Two independent defects, both measured on the live pages. First, the stacked-card layout for narrow screens already existed in `styles/components.css` but was **dead on the Jobs page**: its `.job-row` / `.job-row-link` selectors are `(0,1,0)`, while `styles/jobs.css` set `grid-template-columns` on `.jobs-page .job-row` / `.jobs-page .job-row-link` at `(0,2,0)` with no media query, and a higher specificity beats a lower one regardless of load order. The header-hiding and `::before` label rules in that same block are single-class and had no competitor, so they *did* apply — producing the half-broken hybrid in the reports: `COMPANY` / `LOCATION` / `SAVE` labels injected inline on each row while the six-column desktop grid still ran off the right edge. The desktop track list now lives behind `@media (min-width: 901px)`, the pattern `styles/saved.css` already used, so below 901px `jobs.css` declares no tracks at all and the existing card fallback wins with no change to `components.css`. Second, both tables had a hard intrinsic floor: the Jobs tracks `minmax(19rem,…) minmax(10rem,…) minmax(11rem,…)` plus four fixed columns and gaps cannot shrink below ~1024px, and Saved's floors totalled ~982px, so the table overflowed even in the 901–1048px band where the card layout is correctly inactive. Those fluid tracks now use a `0` floor. Measured page-level horizontal overflow on `jobs.html` before: `+7px` at 1044, `+20px` at 1024, `+84px` at 960, `+335px` at 717, `+662px` at 390, with `Onsite` / `Unknown` chips visually clipped (25px wide needing 57px); after: **zero at every width from 360px to 1440px on both pages**, and no clipped cells. Desktop layout above 901px is unchanged (55px rows), and below 901px rows become the 246px cards that were always intended. Because the layout is now height-dependent, `recalculateItemsPerPage` in `frontend/jobs/app/runtime/events.js` measures a real rendered row instead of trusting the hardcoded `innerWidth <= 900 ? 136 : 52` guess — which was already wrong, since a card row measures 246px, not 136px — and keeps that constant only as a fallback for when no row is available to measure. Three further narrow-width defects were found by measuring the rendered pages rather than the CSS, and all three are fixed. **The Jobs freshness dot sat on top of the job title.** It is absolutely positioned inside the card, and its `left: 2rem` was smaller than the row's own `2.5rem` left padding, so it landed under the first glyph: measured a `-2px` gap between the dot's right edge and the first text rect at 900/811/600/390px. At `left: 1rem` the gap is `+14px` at every one of those widths. **The Saved page's phase bar had a hard 723px floor.** Each of its eight steps carried `min-width: 5.65rem` inside a horizontal flex row, so at 811px the bar alone was 773px wide and the page overflowed by `+9px`, growing to `+40px` at 780, `+220px` at 600, `+340px` at 480 and `+460px` at 360; the steps were never clipped, they simply could not fit. It is now a wrapping grid (`repeat(auto-fit, minmax(4.6rem, 1fr))`) and the connector line is suppressed below 901px, since steps wrapped across several rows have no single straight line to draw through them. Measured page overflow after: `-15px` at every width from 900px down to 360px, with all eight steps visible and none clipped. **The Saved job title could not wrap.** `.saved-job-row .col-title` is a flex row holding the title, the inline source badge and the freshness dot, and without `flex-wrap` those items could not break, so the row exceeded its track and widened the page — the same `+9px`-to-`+460px` overflow above, from a second independent cause. The same fix also restored the title stack's measured width, which was collapsing to `0px` (a `min-width: 0` flex child with nothing to size against) and now measures 183–723px across that range. New guard tests cover the freshness offset, the label alignment, the wrapping phase bar and the wrapping title, and the Saved track assertion moved from `jobs-html.test.mjs` to a dedicated `saved-css-guards.test.mjs` so both sheets own their own guards.

- **The current page in the Jobs pager is now unmistakable in dark theme.** The active page number used to be a soft-tinted chip whose border colour was silently overwritten: `.page-btn.active { border-color: var(--accent) }` in `styles/components.css` and `.jobs-page .page-btn { border-color: var(--surface-20) }` in `styles/jobs.css` are both `(0,2,0)` specificity, and `jobs.css` loads after `components.css` on `jobs.html`, so the jobs override won and painted the current page's border the same grey `#666666` as every other button. Measured on the live page, the active chip differed from its neighbours only by a slightly lighter purple-grey fill and a 12-unit text tint — hence "hard to distinguish". The active rule is now a filled accent chip (`--accent` → `--accent-hover`, dark on-accent text at 6.8:1, 5.2:1 on hover) matching what the light theme already did, and it is scoped as `.pagination .page-btn.active` so the Jobs-page override can no longer outrank it. Inactive buttons and their hover states are byte-identical to before in both themes.

- **The `Update jobs` tooltip is a fixed tip again, and the progress caption leads with what is actually running.** The tooltip had been carrying the technical progress breakdown (`Executing sources · 5/2,052 sources resolved · rate 36/min · ETA 56m`) so that detail was not lost when the caption went plain-language. That reasoning was wrong in practice: the caption directly below already reports progress, so repeating it in the tooltip was noise on hover. The tooltip is now the fixed copy string in every state. The one deliberate exception is the stall/quiet warning (`No progress for 2m.` / `Still working — counts unchanged for 2m.`), which is not progress but a health signal — without it a dead or frozen run would look perfectly healthy, because the caption simply freezes on its last numbers. The caption itself grew from two plain segments to three, ordered phase → count → estimate, e.g. `Executing sources · 512 of 2,135 · ~10m left`: the phase leads because the button label above only names the coarser stage and the tooltip no longer carries the breakdown; the estimate is marked approximate (`~10m left` rather than `ETA 10m`) since it is recomputed on every poll; and the count drops its noun when the phase already supplies it, so it reads `Executing sources · 512 of 2,135` instead of stuttering `… · 512 of 2,135 sources`. That left the technical formatter with no caller at all, so it was deleted along with its five private helpers (`formatFetchCaption`, `formatDiscoveryCaption`, `formatPipelineCaption`, and the two discovery label builders). It was never an Admin surface: Admin renders task progress through `shared/task-run-view-model.js` → `shared/task-progress.js` (`formatTaskProgressDetail`), a separate implementation that never imported this module, so Admin output is unaffected by the removal.

- **Removed the pipeline stage toasts from the Jobs page, and repaired the shared toast styling.** The jobs CTA toasted once per pipeline stage — "Source discovery", "Fetching job listings", "Syncing results", "Finishing up" — a behaviour introduced with the stage-transition feature. Those are internal pipeline stage names, and the CTA caption already reports live progress, so on a user-facing page they were redundant jargon: a single run stacked four of them on top of the start and completion toasts. The frontend no longer reads the status payload's stage-transition list, and the counter that tracked already-seen transitions is gone; the backend still emits the field for Admin diagnostics. Separately, an earlier jobs density pass had overwritten the shared `.toast.info` rule into lowercase micro-text (10.4px, no border, no background, `text-transform: lowercase`) and deleted the `.toast-action-btn` rule outright, so every informational toast rendered as bare lowercase text and the Undo/Revert buttons in saved-page toasts fell back to the browser default (2px outset border, grey background, default cursor). Both shared rules are restored, which fixes those toasts across Jobs, Saved, and Admin.

- **Jobs toolbar spacing, Last-updated placement, and a compact pager.** The caption line sat flush against the `Update jobs` button (a measured 0px gap), so the status row now carries a small `margin-top` and the text no longer reads as crammed. `Last updated` moved off its own right-aligned row onto the button line, pinned to the left edge with `margin-right: auto` while the button stays right-aligned; below 900px — where the button goes full width — the row wraps and the stamp drops to its own line directly above the caption rather than above the button. Because the stamp left the status row, the dim-while-running rule now reads run state from the shared `.jobs-toolbar` ancestor (toggled in `pipeline.js`), so it keeps dimming to `0.55` during a run instead of silently stopping. The pager buttons were 38px tall for ~13px numerals, which read as oversized empty boxes; they are now 28px near-squares with tightened row margins, and the `min-height` reservation on `.jobs-page .pagination` is kept (reduced) so late pagination still cannot shift first paint.

- **The Jobs page update caption now speaks plain language instead of pipeline vocabulary.** The caption under `Update jobs` was reusing the Jobs page's own technical formatter, so an end user could see a raw adapter id and internal counters — the worst case read `Probing candidates · stage 2/5 · probing steam_curator_feeds · 138/500 candidates probed · generated 312 · endpoints 87 · queued 41`. It is now capped at a small number of plain segments, and the phase name is deliberately omitted when a count is shown because the button label directly above already names the stage. Adapter ids, `stage`/`step` markers, `rate N/min`, and the `generated`/`endpoints`/`queued`/`batch`/`URLs`/`pages` counters are filtered out; an unrecognised internal token falls back to the user-facing stage vocabulary rather than being prettified into view (`steam_curator_feeds` must not render as "Steam Curator Feeds"). Admin was never affected either way — it renders task progress through `shared/task-run-view-model.js` → `shared/task-progress.js` (`formatTaskProgressDetail`), a separate implementation that does not import the Jobs pipeline module. The stalled-status caption also drops "Pipeline status delayed; retrying..." for "Still working…". (Two details of this pass were revised later in the same release window: the tooltip no longer carries the technical string, and the caption leads with the phase across three segments — see the `Update jobs` tooltip entry above.)

- **The Jobs update caption shimmers without flashing, and can no longer squeeze the toolbar text.** The caption's live text is now painted from a `background-clip: text` gradient so a soft neutral highlight sweeps through it continuously while a run is active — no colour accent, no per-poll opacity fade, and no overlaying copy of the previous label (an overlaid ghost fought the host's `nowrap`/`ellipsis` clamp, briefly painting "…" over the live text and double-exposing on shrink). The toolbar status row was also rebalanced: `results-summary` and `jobs-last-updated` are now `flex: 0 0 auto` so the progress caption is the only element that yields width, which previously clipped the results summary to `Showing 1-11 of 30,96…` and wrapped the timestamp onto two lines mid-run.
