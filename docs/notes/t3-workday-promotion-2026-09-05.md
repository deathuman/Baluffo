## Runtime registry cache refresh: why it was a two-step fix

The promotion moved the three rows into the active file (`registryState=active`), but a manual promotion outside the running pipeline leaves them in a shape the fetch runtime would still ignore: `enabledByDefault=False` and `candidateState=staged_provider_candidate`. The runtime treats those as gated, so `registry_entries('workday', enabled_only=True)` did not return them until two steps were done:

1. **Refresh the in-process cache** — `reload_studio_source_registry()` re-reads the active file into the module-level `STUDIO_SOURCE_REGISTRY` global, which is populated only once at import time.
2. **Normalize the manual-promotion surface** — `normalize_manual_promotion_rows(...)` (new seam in `src/jobs/registry.py`) rewrites the active file so each promoted row is `enabledByDefault=True` and `candidateState=live`. That's idempotent and scoped to the exact row ids.

After both, a fresh-process import shows the three normalized rows under `registry_entries('workday', enabled_only=True)`, with canonical Workday board URLs (`sciplayexternalcareerssite`, `lightspeed`, `warnerbros.wd5.myworkdayjobs.com/en-us/global?q=avalanche`).
