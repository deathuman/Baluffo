## Closeout

This record is closed as a pre-release approval, not as the release itself. The
`0.2.0` changelog draft now lives in [`../CHANGELOG.md`](../CHANGELOG.md) under
`## [0.2.0] - Unreleased`.

Release-day work remains intentionally separate: update `src/app_version.py`,
set the final changelog date, verify signing secrets, run the canonical release
preflight, build exact-version artifacts, rehearse the staged update from
`0.1.33`, create `v0.2.0`, and publish only after the release owner signs off.

## Summary

Baluffo has accumulated a release-sized set of changes since `v0.1.33`.
The local commit review found `576` commits between `v0.1.33` and `HEAD`
on 2026-05-15, with work concentrated in runtime storage, source-sync,
Admin/Ops observability, source-policy and dedup tooling, packaged desktop
hardening, performance tooling, and repo safety guardrails.

This archived plan approves `0.2.0` as the next public release target after
pre-release review. It does not change the app version, release date, tags,
release assets, manifests, updater metadata, or data schema metadata.

## Main Release Themes

### Runtime Storage Authority

- Added SQLite/WAL runtime storage for task lifecycle, sync runs, source runs,
  jobs feed exports, and source registry rows.
- Added storage health diagnostics and packaged storage validation.
- Preserved compatibility exports so existing frontend and release flows can keep
  reading stable JSON projections where required.

### Source Sync v3

- Added content-addressed gzip shard bundles and schema-v3 source-sync manifests.
- Added sharded reads and writes, changed-shard push detection, bounded shard
  garbage collection, and per-shard push progress.
- Tightened source-sync snapshot limits, validation, idempotency, checkpoint
  tagging, and packaged sync-config verification.

### Admin/Ops Lifecycle Visibility

- Added richer current-run, completed-run, task lifecycle, progress, diagnostics,
  source-policy, and dedup visibility in Admin/Ops.
- Hardened task liveness, fetch completion authority, live task polling, and
  progress projection behavior.
- Added diagnostic copy and evidence-oriented review surfaces without making
  diagnostics the lifecycle authority.

### Source Policy, Registry, and Dedup Tooling

- Added source-policy soak reporting, provider migration advisory evidence,
  manual migration-link review, provider/static overlap checks, and safer static
  suppression proposal flows.
- Added dedup evidence, review queues, monitor-vs-blocking classification,
  Google Sheets role-bucket diagnostics, provider/static disagreement review,
  and lifecycle-readiness gates.
- Corrected registry conflict, provider/static, static-source, and dedup pressure
  handling so monitor-only debt remains visible without blocking lifecycle readiness.

### Packaged Desktop and Release Hardening

- Added packaged storage, jobs-feed parity, fetch evidence, sync rehearsal,
  update rehearsal, orphan-reclaim, browser-job, and jobs-pipeline coverage.
- Included SQLite runtime support and storage modules in packaged and ship-bundle
  paths.
- Hardened desktop startup/session ownership, packaged smoke readiness, runtime
  resource bundling, and release-critical validation paths.

### Performance, CI, and Repo Safety

- Added startup, frontend, bridge, sync, discovery, and fetch benchmark/profiling
  signals.
- Added benchmark workflows, performance baselines, trend reporting, and startup
  regression gates.
- Added gitleaks secret scanning, Python dependency security audit wiring,
  bridge route inventory guardrails, repo-health policies, and broader typed/lint
  guardrails.

### Documentation and Maintainability

- Reorganized active docs around the docs index, release guide, storage/sync
  contracts, source-policy runbook, testing guide, and AI/tooling guardrails.
- Archived completed planning records and kept active plans focused on current
  follow-up work.
- Split many large compatibility roots and runtime files into narrower leaf
  modules while preserving public facades where needed.

## Release Risk Decisions

Pre-release approval decisions:

1. `0.2.0` remains the target public release version.
2. Desktop manifest `data_schema_version=2` remains the expected release value.
3. No named ship-bundle migration plan is approved in this closeout; release-day
   validation must add one only if final staging finds a required data migration.
4. `rollback_allowed=false` remains the default desktop update manifest policy
   unless release-day rollback rehearsal explicitly approves enabling it.

Release-day gates that remain mandatory:

1. Rehearse update from `0.1.33` to `0.2.0` on staging with persisted local data.
2. Confirm storage health, startup readiness, source-sync behavior, and support
   bundle generation after the staged update.
3. Confirm GitHub release secrets and desktop update signing inputs are present
   in the release workflow environment.
4. Confirm release notes can be extracted from the final `docs/CHANGELOG.md`
   `0.2.0` section once it is dated.
5. Keep the previous release available for rollback and incident response.

## Non-Goals For This Closeout

- Do not update `src/app_version.py`.
- Do not create, move, delete, or recreate tags.
- Do not build or publish release artifacts.
- Do not change update manifests, release workflow behavior, updater versions,
  manifest schema versions, or data schema versions.
- Do not add new runtime, Python, or Node dependencies.

## Validation Plan For A Future Release Pass

When release prep begins:

1. Update the app version and changelog on the release commit.
2. Run the canonical release preflight:

   ```powershell
   npm run release:preflight
   ```

3. Build exact-version artifacts:

   ```powershell
   npm run build:ship-bundle -- --bundle-version 0.2.0
   npm run build:portable-exe -- --bundle-version 0.2.0
   ```

4. Rehearse packaged desktop update from `0.1.33` to `0.2.0`.
5. Validate release-note extraction from `docs/CHANGELOG.md`.
6. Publish only after staged startup, update, storage health, local-data
   preservation, source-sync, and rollback expectations are signed off.

## Assumptions

- `0.2.0` is intended as a larger public release-line bump after the post-`0.1.33`
  improvement wave.
- The release is not intended to break current saved-job, bridge, storage export,
  or source-sync compatibility surfaces.
- Active advisory/future plans remain deferred unless explicitly added to the
  `0.2.0` release scope.
- This document is an archived pre-release approval record. Release metadata,
  final changelog date, tags, and release artifacts remain owned by the later
  release pass.
